# qtflow-state

面向自研平台的商务流程状态数据底座。

将量潮 E1 至 E18 邮件工作流中的状态信号沉淀为结构化数据，使流程状态在过渡期（邮件）与平台期（qtcloud-business / qtdata）均保持可见、可回溯、可校验。

状态数据层独立于上层载体设计，可为量潮执行云（qtcloud-execute）等自研系统提供执行状态数据。

## 30 秒上手

无需配置环境，三条命令跑通全链路。

```
python project/parser.py
python scripts/verify_delivery.py
cat project/data/parsed_states.json
```

Windows 用户更简单：直接双击 `run-demo.bat`，自动完成解析与自检。

**看到这个输出就说明装好了**：

```
qtflow-state 交付自检
--------------------------------------------------
  [PASS] 示例邮件存在 —— 共 1 个文件
  [PASS] 解析器可导入
  [PASS] E1.txt 关键字段抽取 —— 项目=某某高校科研数据项目 节点=E1
  [PASS] 证据字段完整 —— 每条记录均保留 evidence
  [PASS] JSON 输出可回读 —— 1 条记录

交付自检通过
```

只要出现 `结果：5/5 项通过` 和 `交付自检通过`，环境就是好的。任何一项 `FAIL` 都会直接告诉你哪一步出问题。

## 输出示例

解析结果写入 `project/data/parsed_states.json`，单条记录形如：

```json
{
  "project": "某某高校科研数据项目",
  "node": "E1",
  "subject": "[某某高校科研数据项目] - 合作承接确认与信息收集",
  "actor": "商务经理",
  "date": "2026-08-15",
  "expected_response": "请您提供以下信息（如有资料可直接回复附件）：",
  "evidence": "主题：[某某高校科研数据项目] - 合作承接确认与信息收集 X老师您好，...",
  "source": "E1.txt",
  "parsed_at": "2026-09-01T16:38:00"
}
```

每个字段的含义、抽取规则、抽不到时怎么办，见 [字段口径说明](docs/字段口径说明.md)。

## 设计原则

三条原则决定了这套东西的定位。

第一，每条记录都保留证据。所有抽取结果都附带 evidence 原文，供人工复核，不要求使用者盲信系统的判断。

第二，抽取失败返回空值。字段无法确定时返回 null，不做猜测，不填充默认值。宁可留空，不可编造。

第三，只抽取事实，不判断对错。状态是否异常由人判定，系统只负责把事实摆到面前。

这三条指向同一个定位：本仓库交付的是质量检查工具，不是自动化决策工具。这一点与课题来源方在需求讨论中表达的偏好一致——自动化容易找到替代，质量控制非常稀缺。
