# 调研笔记

## 痛点来源（群内原话）

- 赵子奕：邮箱自动化的主要难点在于，你需要读海量的上下文，
  都不一定能猜得出它的实际状态。规则稍微一乱一下就没法读了。
- 张果：项目前期一般看起来正常，一到中后期就开始出问题，
  特别是后期；几个项目堆一起时，整个团队的协同就立刻卡顿。
- 张果：我们想要质量检查和控制工具，不是自动化工具。
- 张果：验收这一块实际上主要就是数据质量，目前合同也比较模糊，
  我们也在想办法把这块的标准给明确一下。

## 仓库实证

- qtcloud-business README：CLI 当前版本只做无状态计算，
  不保存报价单，也不读取服务端数据。
- qtcloud-business 已有报价/合同/履约三个数据模型，
  前端已有状态徽章组件。
- qtcloud-business 8/23 提交：章程执行率汇总与操作人署名留痕。
- qtdata 采用 Python FastAPI 服务端 + pytest 测试体系。

## 前提认知

邮件工作流本身是过渡方案，各业务正在自研系统并配套后台。
因此本课题不优化邮件流程本身，而是提供跨载体的状态数据层。
